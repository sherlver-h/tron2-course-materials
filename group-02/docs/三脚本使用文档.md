# TRON2 三个演示脚本使用文档

本文档覆盖以下三个脚本的使用方法与注意事项：

| 脚本 | 类型 | 演示入口（examples/） | 虚拟环境 |
|---|---|---|---|
| `demo_color_sort.py` | 仿真 + 视觉（无真机） | `group-02/examples/demo_color_sort.py` | `.venv-vision` |
| `run2_dance_real_robot.py` | 真机舞蹈 | `group-02/examples/run2_dance_real_robot.py` | `.venv-humble` |
| `run2_moves_show_real_robot.py` | 真机动作秀 | `group-02/examples/run2_moves_show_real_robot.py` | `.venv-humble` |

`examples/` 下的三个脚本是薄封装入口：自动切换工作目录、创建输出目录后转交
`src/python/vision/` 或 `src/python/robot/` 下的真实实现执行，参数原样传递。

### 环境与测试准备
```bash
# 两个虚拟环境分别安装依赖（.venv-vision 与 .venv-humble 不要混用）
pip install -r group-02/src/python/vision/requirements.txt   # 视觉仿真
pip install -r group-02/src/python/robot/requirements.txt    # 真机 SDK

# 单元测试（24 项：mock WebSocket 契约 20 + 视觉生成约束 4）
cd group-02 && python -m unittest discover -s tests -v
# 首次先装：pip install -r tests/requirements-test.txt
```

## 1. demo_color_sort.py —— 视觉颜色分拣（纯仿真）

### 功能说明
在 MuJoCo 四臂（2×2 工位）仿真场景中，每个工位桌面上有一个红色干扰块和一个指定颜色的目标块。每个工位上方的俯视相机拍摄图像，脚本用 HSV 颜色分割找到目标色块，将像素坐标反投影为世界坐标 xy，然后由对应机械臂规划抓取路径——是真实的"视觉定位 → 抓取"流水线，不是固定坐标。

- 视觉中间结果（叠加质心的 RGB 图 + mask）保存到 `results/color_sort/`
- 运行日志会打印每个工位色块的生成位置和视觉检测位置，可对比验证精度

### 运行命令
```bash
cd tron2-course-materials/group-02/examples
source <课程环境>/.venv-vision/bin/activate   # 含 mujoco / opencv / numpy 的环境

# 实时窗口（需要图形环境 / X11 转发）
python demo_color_sort.py --show --video

# 仅无头录像（生成 results/four_arms.mp4 和截图，不产生窗口）
python demo_color_sort.py --video

# 自定义各工位目标颜色与随机种子
python demo_color_sort.py --colors blue green red green --seed 3 --video
```

### 参数
| 参数 | 默认 | 说明 |
|---|---|---|
| `--show` | 关 | 弹出 MuJoCo 实时窗口 |
| `--video` | 关 | 无头渲染，输出 mp4 + png |
| `--colors` | `blue green blue green` | 4 个工位的目标颜色（blue/green/red） |
| `--seed` | 1 | 色块随机生成位置种子 |
| `--render-every` / `--fps` | 8 / 40 | 视频抽帧与帧率（40fps + every-8 ≈ 3× 慢动作） |

### 注意事项
1. **这是纯仿真脚本**：不需要连接机器人，也不要加 `--send`/`--robot` 参数。
2. **图形环境**：`--show` 需要可用的显示（本机桌面或 X11 转发）；纯 SSH 无显示环境请只用 `--video`（MuJoCo 用离屏渲染），否则会因无法创建 OpenGL 上下文而失败。
3. **虚拟环境**：必须在 `.venv-vision` 下运行（含 `mujoco`、`opencv-python`、`numpy`）；`.venv-humble` 是给真机 SDK 用的，混用会缺包。
4. **检测失败**：若某工位颜色检测失败（光照/遮挡/色块出界），脚本直接 `RuntimeError` 中止；可换 `--seed` 重试。
5. 色块生成区域有安全约束（与红色干扰块、放置点保持 ≥0.10 m），无需担心生成到不可达位置。

## 2. run2_dance_real_robot.py —— 双臂街舞（真机）

### 功能说明
60 拍的预编排双臂街舞（intro → robot_isolation → verse_pointing → chorus_swing → breakdown_clap → outro_freeze），包含 MoveJ 关节动作、夹爪开合和头部动作。默认 `--duration 3.0` 时全长恰为 180 s；真机要求每拍 ≥ 5 s，所以 `--duration 5` 时全长 300 s（5 分钟）。所有命名姿态都逐个关节核对过限位（左右肩 roll 限位不允许交叉手臂）。

### 运行前准备（每一步都必须做）
```bash
cd tron2-course-materials/group-02/examples
source <课程环境>/.venv-humble/bin/activate
```
0. **准备 profile**：仓库中不提供真实 `device_A.json`（含内网 IP 与机器人 SN）。以 `group-02/data/robot_profile.example.json` 为模板，填入真机 `url`、`accid`、关节名后保存为 `device_A.json`（放在工作目录或任意路径，用 `--robot` 指定）。
1. **网络**：网线连接机器人，本机 IP 设为 `10.192.1.x`（如 `10.192.1.120`），`ping 10.192.1.2` 通。
2. **核对机器人**：浏览器打开 `http://10.192.1.2:8080`，确认 SN 与 `device_A.json` 中 `accid` 一致。
3. **切换模式**：遥控器 **L1+□** 进入 Idle，再按 **R1+右键** 切换到**上层开发者**模式；`device_A.json` 中需 `"mode_confirmed": true`。
4. **确认 `device_A.json` 有效**：`min_segment_s: 5.0` 表示真机每段至少 5 s；`arm_state_names` 为空时先跑一次 `query` 生成 profile 草稿。

### 运行命令
```bash
# 离线预览（不发任何指令，只生成示意报文）
python3 run2_dance_real_robot.py dance --output results/dance_preview.json

# 真机执行
python3 run2_dance_real_robot.py dance --send --robot device_A.json \
       --duration 5 --output results/dance_live.json

# MuJoCo 仿真（可视化，无需真机/网络；需在 .venv-vision 下运行）
python3 run2_dance_real_robot.py dance --sim --duration 3                    # 实时窗口
python3 run2_dance_real_robot.py dance --sim --duration 3 \
       --sim-video results/dance_sim.mp4                                    # 无头录像
```

`--sim` 由 `mujoco_client.py`（与 `client.py` 接口兼容的仿真客户端）驱动官方
MuJoCo 模型运动学插值执行同一套 60 拍编排：关节走 smoothstep 插值，夹爪开合与头部
动作同样可视化；`--sim-video <路径>` 在无显示环境输出 mp4（帧率 `--sim-fps`，默认 30）。
与 `--send`/`--robot` 互斥。

### 参数
| 参数 | 默认 | 说明 |
|---|---|---|
| `dance` | — | 动作子命令（另有 query/prepare/movej/movep/gripper 等教学命令） |
| `--send` | 关 | 不加则只离线预览；真机必须加 |
| `--robot` | — | 真机 profile JSON（含 url、accid、关节名、限位），会替代 `--host/--port/--accid` |
| `--duration` | 3.0 | 每拍时长。真机必须 ≥ profile 的 `min_duration`（device_A 为 5 s），范围 1–30 s |
| `--speed` / `--force` | 30 / 20 | 夹爪速度/力度（0–100） |
| `--output` | `sdk_result.json` | 结果 JSON 路径（`.events.json` 事件日志自动一并生成） |

### 注意事项
1. **安全第一**：执行 `--send` 后会提示 `Real robot will move... Type y to send`。必须先核对打印的目标数值、清空手臂活动范围、**人手放在急停上**，才能输入 `y`。舞蹈只确认这一次，之后 60 拍连续执行不再暂停。
2. **急停后果**：急停会断电，手臂会直接落下——手臂下方不要放任何物品。
3. **时长下限**：真机 `--duration` 必须 ≥ 5 s（device_A.json 的 `min_segment_s`），否则直接报错拒绝发送。
4. **真机禁用项**：`servoj`、`drag`（状态修改类）、`compliant` 开关在真机模式下被禁用；单段关节跳变超过 0.1 rad 的动作会要求额外确认（舞蹈的大角度姿态由整段编排的一次性确认覆盖，属预期行为）。
5. **夹爪**：若 profile 中夹爪不可用，脚本会自动探测并在舞蹈中跳过夹爪拍（保持节拍计时），不会中途崩溃。
6. **节奏保真**：每个 MoveJ 后脚本会等待关节到位（`wait_joints`）才发下一拍，确保节拍不被覆盖；ctrl+C 后请重新 `query` 确认机器人状态再复位。
7. **输出文件**：结果写入 `results/dance_live.json`（含每拍计数与总时长），事件时间线在同名 `.events.json`，可用于复盘每个报文的往返延迟。

## 3. run2_moves_show_real_robot.py —— 动作串烧秀（真机）

### 功能说明
由 `run2_moves_real_robot.py` 动作库编排的固定节目单（63 拍，比舞蹈多 3 拍）：

```
nod → wave → point_scan → jab_combo → open_close → chest_beat
    → head_bop → swing → robot_step → freeze → bow
```

节奏设计：慢速开场（点头/挥手）→ 高潮（chest_beat/swing）→ robot_step + freeze 收尾 → 鞠躬结束。默认 `--duration 3.0` 时约 189 s；真机 5 s/拍时约 315 s。

### 运行命令
```bash
cd tron2-course-materials/group-02/examples
source <课程环境>/.venv-humble/bin/activate

# 查看节目单（节拍数 / MoveJ·夹爪·头部数量 / 最大单拍跳变，不发指令）
python3 run2_moves_show_real_robot.py list --robot device_A.json --duration 5

# 离线预览
python3 run2_moves_show_real_robot.py show --output results/show_preview.json

# 真机执行
python3 run2_moves_show_real_robot.py show --robot device_A.json \
       --send --duration 5 --output results/show_hw.json

# MuJoCo 仿真（可视化，无需真机/网络；需在 .venv-vision 下运行）
python3 run2_moves_show_real_robot.py show --sim --duration 3                 # 实时窗口
python3 run2_moves_show_real_robot.py show --sim --duration 3 \
       --sim-video results/show_sim.mp4                                      # 无头录像
```

### 参数
| 参数 | 默认 | 说明 |
|---|---|---|
| `show` / `list` | — | `show` 播放节目；`list` 只打印节目单（advisory，不发任何报文） |
| `--send` | 关 | 真机必须加；否则离线预览 |
| `--robot` | — | 同舞蹈脚本 |
| `--duration` | 3.0 | 每拍时长，真机 ≥ `min_duration`（5 s） |
| `--speed` / `--force` | 30 / 20 | 夹爪速度/力度（0–100） |
| `--output` | `sdk_result_show.json` | 结果 JSON 路径 |

### 注意事项
1. 网络、模式切换、`y` 确认、急停、时长下限等安全要求与舞蹈脚本**完全相同**（两脚本共用 `client.py` 的连接与确认机制）。
2. **`list` 是很好的预检工具**：真机运行前先跑 `list --robot device_A.json --duration 5`，确认每拍时长、总时长和有无超出单段限位的告警。
3. 超过 `max_segment_delta_rad`（0.1 rad）的大角度拍会标注 `[超单段... rad]`，属预期——与舞蹈一样由整段的一次性确认覆盖。
4. 结果写入 `results/show_hw.json`，事件日志在同名 `.events.json`。
5. 本脚本 `--robot` 时 `require_names=True`：profile 的 `arm_state_names` 必须已填好 14 个关节名（先用 `run2_dance_real_robot.py query --robot device_A.json --send` 生成草稿并核对），否则拒绝运行。

## 4. 常见问题（FAQ）

| 问题 | 排查 |
|---|---|
| 真机脚本报 `duration` 相关 ValueError | 真机每段 ≥ profile 的 `min_segment_s`（device_A 为 5 s），加 `--duration 5` |
| `ping 10.192.1.2` 不通 | 检查网线、本机 IP 是否在 `10.192.1.x` 网段 |
| 连接被拒 / 超时 | 确认遥控器已切到**上层开发者**模式（Idle → R1+右键），且 `mode_confirmed: true` |
| `arm_state_names` 为空报错 | 先跑 `query --send` 生成 `.profile_draft.json`，人工核对 14 个名字后回填到 `device_A.json` |
| `demo_color_sort.py` 打不开窗口 | 无显示环境，去掉 `--show` 只留 `--video` |
| `demo_color_sort.py` 报缺 mujoco/cv2 | 跑错环境了，必须用 `.venv-vision` |
| 真机脚本报缺包 / import client 失败 | 跑错环境了，必须用 `.venv-humble`；直接用 `examples/` 入口可忽略 cwd 问题（wrapper 自动切目录），手动调用真实脚本时才需要 cwd 在 `src/python/robot/` |
| `--sim` 报缺少 mujoco | `--sim` 模式需要 mujoco，必须在 `.venv-vision` 下运行（真机模式才用 `.venv-humble`） |
| 颜色检测失败 RuntimeError | 换 `--seed` 重试，或检查 `results/color_sort/` 下的 mask 图定位原因 |

## 5. 三个脚本的依赖关系速览

```
demo_color_sort.py
  └─ 依赖 demo_four_arms.py（场景/解析/runner）→ 只需 .venv-vision（mujoco, opencv, numpy）
  └─ 依赖 build_scene.py + 本目录 official/（机器人 XML 与 meshes，必须一起存在；
     meshes 为 51MB 官方模型**不在仓库中**，需从课程环境 `Course_Code/vision_examples/official/meshes` 复制）

run2_dance_real_robot.py
  └─ 依赖同目录 client.py, lessons.py, run2_moves_real_robot.py → 只需 .venv-humble + device_A.json + 机器人网络
  └─ --sim 模式改由 mujoco_client.py 驱动（复用 vision/official 模型，需 .venv-vision）

run2_moves_show_real_robot.py
  └─ 依赖 client.py, run2_moves_real_robot.py（动作库 MOVES）→ 同上

说明：`src/python/robot/run.py` 是配套仿真教学脚本，被 `tests/test_contract.py` 引用，不参与真机演示。
```
